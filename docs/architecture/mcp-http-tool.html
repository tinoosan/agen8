Architecture · MCP HTTP Tool

MCP HTTP tool

The agent-facing integration tool for making bounded HTTP requests with host-scoped credentials.

Purpose

http is an MCP tool, not a generic runtime module. It exposes one product-facing operation: make an outbound HTTP request, optionally injecting credentials resolved by host. The handler owns request decoding, URL validation, credential lookup, HTTP execution, response truncation, and deterministic result shaping.

Boundary. HTTP tool behavior lives in internal/mcp/tools/http. The credential service owns stored secrets and metadata. The HTTP client is package-local tool infrastructure. No service accepts raw http(...) tool JSON, no service package defines an HTTP-tool-specific service or port, and no MCP session imports an HTTP client from another runtime package.

Operation

Tool callHandler responsibilityDependenciesResult
http(...) Validate method and URL, resolve host credentials, inject auth, execute the request with package-local clients, cap response size, and format the response. CredentialSvc.Get plus package-local net/http clients. Status, final URL, response headers, text body preview, truncation state, and credential injection metadata.

Control flow

Application wiring

The application composition root constructs CredentialSvc once. When MCP session bootstrap registers a session for a managed harness, it includes that concrete service as the handler's narrow credential resolver. The HTTP clients are not supplied by the session; they are created inside the HTTP tool package.

// MCP session bootstrap
tokenStore.Register(token, agen8mcp.Session{
    CredentialResolver: app.CredentialSvc,
    ProjectID:          strings.TrimSpace(projectID),
})

// internal/mcp/server.go
http.NewHandler().Handle(ctx, http.CallContext{
    Credentials: session.CredentialResolver,
    ProjectID:   session.ProjectID,
}, arguments)

Handler contract

The handler receives only credential resolution and project identity from the MCP session. Network execution is package-owned infrastructure.

type CredentialResolver interface {
    Get(ctx context.Context, owner credentialdomain.CredentialOwner) (credentialdomain.CredentialRecord, error)
}

type CallContext struct {
    Credentials CredentialResolver
    ProjectID   string
}

type Handler struct {
    client           *http.Client
    noRedirectClient *http.Client
    defaultMaxBytes  int
    maxBytes         int
}

func NewHandler() Handler
func (h Handler) Schema() json.RawMessage
func (h Handler) Handle(ctx context.Context, call CallContext, args json.RawMessage) (Result, error)

Request model

FieldRule
urlRequired absolute HTTP or HTTPS URL.
methodRequired. One of GET, POST, PUT, PATCH, DELETE, HEAD.
params_listOptional key/value query parameters. Omit when there are no extra query parameters.
headers_listOptional key/value request headers. Omit when there are no extra headers.
bodyOptional request body. Rejected for GET and HEAD.
maxBytesOptional response cap. Zero uses the package default. Values above the package maximum are rejected.
timeoutMsOptional per-request timeout. Zero uses the package default client timeout.

Credential lookup

Credentials are resolved by request host. The handler checks the project-scoped credential first, then the global credential. Anonymous HTTP remains valid when no credential exists; malformed credential records fail loudly.

Lookup orderOwner typeOwner idMeaning
1 http_endpoint_project <project id>:<host> Project-specific credential for the endpoint host.
2 http_endpoint_global <host> Global credential for the endpoint host.

The handler injects supported auth records into the outbound request. Unsupported auth shapes return a tool error instead of silently sending an unauthenticated request.

Result rules

RuleWhy it exists
Result content is structured and deterministic.Transcript cards render known fields instead of debug blobs.
Text bodies are capped by byte limit.Tool output remains bounded and predictable.
Binary response bodies are omitted explicitly.Agents see bodyOmitted=true and a reason, not corrupted text.
Credentials are never echoed.Result metadata may say whether credentials were injected, but not their values.
Credential lookup failures fail loudly except not-found.Missing credentials means anonymous request; broken credential storage means a real error.
