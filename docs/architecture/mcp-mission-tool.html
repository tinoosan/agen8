Architecture · MCP Mission Tool

MCP mission tool

The agent-facing strategy tool. It exposes missions and key results through one native MCP handler backed by the mission service.

1. Boundary

mission is an MCP adapter. It owns tool action names, JSON decoding, session caller resolution, context stamping, and deterministic MCP output. The mission service owns mission lifecycle, KR lifecycle, measurement rules, progress persistence, and mission events.

Service rule. The handler calls service methods only. It never imports mission infra, repositories, RPC DTOs, or a generic tool runtime.

2. Wiring

internal/mcp/toolset.go registers mission.NewHandler().Schema(). internal/mcp/server.go resolves the token into a Session, dispatches native mission calls, and passes the mission service through narrow handler-owned interfaces.

3. Handler interfaces

type MissionLifecycleService interface {
    CreateMission(context.Context, missionapp.CreateMissionParams) (mission.Mission, error)
    GetMission(context.Context, mission.MissionID) (mission.Mission, error)
    ListMissions(context.Context, string, mission.MissionFilter) ([]mission.Mission, error)
    UpdateMission(context.Context, missionapp.UpdateMissionParams) (mission.Mission, error)
    DeleteMission(context.Context, missionapp.DeleteMissionParams) (mission.Mission, error)
}

type KeyResultService interface {
    CreateKeyResult(context.Context, missionapp.CreateKeyResultParams) (kr.KeyResult, error)
    GetKeyResult(context.Context, kr.KeyResultID) (kr.KeyResult, error)
    ListKeyResults(context.Context, mission.MissionID) ([]kr.KeyResult, error)
    UpdateKeyResult(context.Context, missionapp.UpdateKeyResultParams) (kr.KeyResult, error)
    AssignKeyResultSpace(context.Context, kr.KeyResultID, string) (kr.KeyResult, error)
    DeleteKeyResult(context.Context, missionapp.DeleteKeyResultParams) (kr.KeyResult, error)
    ReopenKeyResult(context.Context, missionapp.ReopenKeyResultParams) (kr.KeyResult, error)
}

type ProgressService interface {
    UpdateProgress(context.Context, missionapp.UpdateProgressParams) (kr.KeyResult, error)
    GetProgressHistory(context.Context, kr.KeyResultID) ([]kr.ProgressEntry, error)
    ComputeMissionProgress(context.Context, mission.MissionID) (missionapp.MissionProgress, error)
}

The interfaces are intentionally small. They are defined where the handler consumes them, and *missionapp.Service satisfies them without an adapter.

Lifecycle actions are idempotent when the target state is already present. Repeating activate on an active mission, complete on a completed mission, archive on an archived mission, or kr_drop on a dropped KR returns the current record without publishing duplicate bus events. When an accepted action includes note, the MCP response echoes it at the top level and the service includes it in lifecycle history; state-changing actions also publish the lifecycle event. The history action reads those persisted lifecycle event payloads with limit and offset.

5. Hard rules

RuleEnforced by
The mission tool never calls repositories.Handler imports only mission app/domain and member domain packages.
The mission service never knows MCP action names.Actions live under internal/mcp/tools/mission.
Unknown fields fail before service calls.Decoder uses DisallowUnknownFields.
Callers include only fields used by the selected action.The schema requires only action; the decoder rejects fields that belong to a different action and rejects explicit null values.
The MCP result is structured and deterministic.Formatter maps mission/KR domain records into canonical result objects.
Session caller identity is stamped before service calls.Handler resolves MemberDirectory.GetMember and writes caller.Caller to context.
