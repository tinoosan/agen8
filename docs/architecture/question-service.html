Architecture · Question Service

Question Service

The question service owns durable question state and answer lifecycle. It can persist a question as a decision when AsDecision is set, using a caller-owned port so it does not import the decision service application API.

On this page

1. Architecture

internal/services/question/app provides the question orchestration boundary: it validates inputs, loads and persists question state, emits question lifecycle events, and owns the DecisionLogger port used only when a question is answered as a decision. 

type Service struct {
  questions domain.Repository
  clock     domain.Clock
  events    EventPublisher
  decisions DecisionLogger
}

type DecisionLogger interface {
  LogDecision(ctx context.Context, req LogDecisionRequest) (DecisionLogResult, error)
}

2. Decision logging seam

The seam is triggered after answer validation when answered.AsDecision is true in question/app. The service calls the local port only after building a decision request payload from the current question state. 

if answered.AsDecision {
  decision, err := s.decisions.LogDecision(ctx, LogDecisionRequest{
    ProjectID:    answered.ProjectID,
    MemberID:     answered.Answer.AnsweredByMemberID,
    Title:        decisionTitle(answered.Text),
    Rationale:    answerSummary(answered),
    Context:      fmt.Sprintf("Answer recorded for question %s.", answered.ID),
    Confidence:   1,
    TaskRef:      answered.TaskRef,
    KeyResultRef: answered.KeyResultRef,
    MissionRef:   answered.MissionRef,
  })
  ...
}

The mapping contract is intentionally caller-owned. The question service keeps its own request/response DTOs and does not couple itself to decision service application types.

3. Composition-root adapter

The concrete adapter is internal/app/question_decision_logger.go. It translates questionapp.LogDecisionRequest into decisionapp.LogRequest, calls the decision service, and returns a questionapp.DecisionLogResult. 

type decisionLogService interface {
  Log(ctx context.Context, req decisionapp.LogRequest) (decisionapp.Result, error)
}

This file is the cross-service seam: it is allowed to import both services because it lives in internal/app.

4. End-to-end coupling path

  1. internal/services/question/app/service.go calls s.decisions.LogDecision when a question is answered as a decision.
  2. internal/app/application.go injects newQuestionDecisionLogger(decisionSvc) into the question service config.
  3. internal/app/question_decision_logger.go maps request/response types and forwards to the decision service.
  4. Decision persistence returns in decisionapp.Result and the decision ID is attached to the answered question and question event.
