Strategy Map Lenses

The strategy map uses lenses to reveal work context without turning every relationship into an expensive animated edge.

1. Lens model

A strategy-map lens is a derived render state over the current React Flow nodes and edges. It does not change graph data. It returns three sets that node and edge components use to decide opacity, stroke weight, and labels:

SetMeaningEffect
clusterNodeIdsNodes inside the active lens.Nodes outside the set dim.
clusterEdgeIdsEdges inside the active lens but not necessarily direct.Edges render as ambient context: visible, lower emphasis, no forced label portal.
directEdgeIdsEdges that receive the expensive direct treatment.Structural edges become bold. A context edge would also mount a label portal and infinite dash animation, so context edges must never enter this set.
Invariant. A contextEdge can be visible and ambient, but it is never direct. This is enforced across set-highlight filters, plain node focus, and the trace lens model.

2. Set-highlight filters

The set-highlight filters are global map lenses selected by preset: in_motion, blocked, done, and decisions. Each preset computes a match set and dims everything else.

PresetMatched nodesEdges
in_motionActive missions, on-track key results, active tasks, and tasks in review.Edges whose endpoints are both inside the matched set, with structural parents included so leaves do not float.
blockedBlocked tasks, at-risk key results, paused missions, and both endpoints of blocked_by context links.Edges whose endpoints are both inside the matched set, with structural parents included.
doneCompleted or archived missions, completed or dropped key results, and succeeded or canceled tasks.Edges whose endpoints are both inside the matched set, with structural parents included.
decisionsEvery decision node plus the far end of context links touching a decision.Only context edges that touch a decision. Structural tree edges stay dim so the lens surfaces reasoning rather than relighting the whole tree.

Set-highlight filters never populate directEdgeIds. In useStrategyMapLenses, a filter result returns directEdgeIds: NO_DIRECT_EDGES, while matched edges stay in clusterEdgeIds. This lets broad filters reveal large slices of the decision web through opacity without mounting hundreds of labels or animations.

3. Focus-neighborhood path

Plain node selection uses the focus-neighborhood path. A focused node reveals the focused node plus every one-hop neighbor across both structural and context edges. Then every edge whose endpoints both sit in that neighborhood becomes ambient.

Only structural edges touching the focused node become direct. Context edges touching the focus still appear because both endpoints are in clusterEdgeIds, but they remain ambient. This is the final gap closed by decision dec-a466fd62-b2b3-4048-ab8a-e99056a87d47: before that change, a high-degree node focus could mark many context links as direct and crash iOS WebKit.

4. Trace stepping model

The trace lens records a progressive path model for walking outward from a focused node one phase at a time. It is anchored on the focus cursor, not the detail panel, so first-touch focus can drive trace without opening the panel.

The trace model alternates phases:

  1. Odd steps are structural. The lens expands the structural frontier by one hop along statusEdge lineage.
  2. Even steps are context. The lens layers in contextEdge links from every node already revealed.
  3. The structural frontier only advances on structural edges. Nodes added through context links do not re-root the structural skeleton, so structural ring N remains exactly N structural hops from the anchor.

The depth range is bounded by TRACE_MIN_DEPTH, TRACE_INITIAL_DEPTH, and TRACE_MAX_DEPTH. The minimum avoids a useless bare-anchor trace. The initial depth gives the user a meaningful first reveal. The maximum caps the number of alternating structural and context phases so a trace cannot light the whole graph at once.

Current-source note. The trace implementation has moved during the context-map cleanup. The durable model is captured here from decisions dec-bd487b73-b2bd-48fb-8528-e23eb218380d and dec-a466fd62-b2b3-4048-ab8a-e99056a87d47, and from the strategy-map interaction section in frontend-behavior.html. If trace returns to the UI, this stepping model is the baseline to preserve unless a new decision supersedes it.

5. Direct versus ambient edges

The direct/ambient distinction exists because context edges are expensive when direct. ContextEdge.tsx renders direct context edges with:

  • a higher-emphasis stroke;
  • a visible label through EdgeLabelRenderer;
  • an infinite context-dash-flow animation when the map is not actively being dragged or zoomed.

That treatment is safe for a handful of structural edges. It is not safe for high-degree context neighborhoods. A direct flood mounts many label portals and perpetual animations, which has repeatedly crashed iOS WebKit with the Safari "a problem repeatedly occurred" failure. Ambient context edges avoid the expensive path: they stay visible through clusterEdgeIds, but they do not force labels or animations.

6. Rendering invariants

InvariantWhy it matters
Context edges are never direct.Prevents the label-portal and infinite-animation flood that crashes iOS WebKit.
Set-highlight filters use opacity contrast, not direct edges.Large filters can reveal broad context without turning every matched edge into an animated element.
Focus-neighborhood directness is structural-only.A node with many decisions or lateral links remains selectable on low-memory clients.
Trace expands structure and context in alternating phases.The user can read lineage first, then reasoning context, without the structural skeleton being pulled around by decision links.
Structural frontier advances only on structural edges.Context-added nodes do not create surprise lineage expansion.
