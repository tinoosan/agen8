Architecture · Workspace binding

Projects, Workspaces & Link Tokens

How a local folder proves which logical Agen8 project it belongs to, and how an agent session registers into that project — without using the absolute folder path as identity.

Marker over path. Project identity comes from the .agen8 marker inside a folder, validated server-side through its wlt_ link token. The legacy path hash (ProjectIDForLocationRoot) survives only as a fallback for unmarked and legacy folders — it never overrides a marker.

1. The problem

An agent harness — Codex or Claude Code — runs inside a folder on a developer machine. Today, when that harness connects to Agen8 over MCP, the project it lands in is derived from a hash of the folder's absolute path (ProjectIDForLocationRoot). That makes the filesystem path the identity of the work. It breaks the moment the same logical project lives at a different path on a different machine, and it offers no way for the server to trust a claimed project_id — any caller could assert any id.

Two things must be true instead:

  • A local folder resolves to the correct logical Agen8 project, decided by a marker inside the folder, not by where the folder happens to sit on disk.
  • The agent session registers as a member of that project, with the project binding established server-side from a credential the caller holds — not from an unauthenticated, spoofable field.

The design splits cleanly into two orthogonal identity axes (section 7), introduces one new credential type and one new domain entity, and reuses the local shim that already exists. It deliberately keeps the path-hash behaviour alive as a fallback, so unmarked folders and existing data keep working.

2. Project, Workspace, Member

The core reframe is a one-to-many relationship that does not exist in the schema today. A Project owns many Workspaces. A Workspace is one place the project is checked out. A Member is one harness session working in it.

Logical · system of record
Project
The shared body of work. Lives on the server (local daemon or hosted). Owns missions, tasks, decisions, the work graph, and the member roster. Identity is a durable project_id, never a path. exists today
Physical · new entity
Workspace
One (location, root, machine) linked to a project. A project has many: the laptop checkout, the CI box, a second machine. Carries display + last-seen metadata. Created when a marked folder first registers. new
Session · actor identity
Member
One harness session registered into a project, keyed by (project_id, harness_kind, native_session_ref). Unchanged by this design. Active members have equal project-level rights in the public baseline. exists today

Git is the closest mental model and the one the design borrows from deliberately:

3. The .agen8 marker

A marked folder carries a small .agen8/ directory, the analogue of .git/. It is split into a committed pointer and a gitignored secret, mirroring how a repo commits .gitmodules but never commits credentials.

Committed · shared
./.agen8/workspace.json
Says which project this folder is, and where its server lives. Safe to commit; identical for every teammate cloning the repo. Carries no secret.
Gitignored · personal
./.agen8/token
The wlt_ link token. Personal to one user, like git credentials. Minted per user, never committed. A generated ./.agen8/.gitignore excludes it by default.
./.agen8/
  workspace.json     # committed — the pointer
  token              # gitignored — the secret
  .gitignore         # generated — contains: token
// ./.agen8/workspace.json  (committed)
{
  "server_url": "https://agen8.example.com",
  "project_id": "agen8-app-1a2b3c4d",
  "workspace_id": "ws-9f8e..."      // optional, server-assigned, cached for display
}

// ./.agen8/token  (gitignored, one line)
wlt_8c1f2a...9b

The pointer is authoritative about which project. The token is the credential that proves which user may bind a session to that project. workspace_id is optional: the server derives the workspace from the token plus the reported (location, root, machine), and may return an id the marker caches for stable display. It is never required for identity.

No silent fallback inside the marker. If workspace.json exists but is malformed, or names a project the token is not bound to, the shim fails loudly. A broken marker is an error to surface, not a reason to silently drop back to path-hash identity.

4. Identity resolution

Project identity is resolved in a strict priority order. The marker wins when present; the path hash is the last resort, kept only so unmarked folders, legacy rows, and first-time discovery keep working.

1Link-token binding. The session carries a project_id bound server-side from its wlt_ token. This is authoritative and cannot be overridden by request input.
2Explicit project_id. A caller with no token binding (e.g. the bootstrap agen8-local token) may still pass an explicit id, as today.
3Path-hash fallback. With neither binding nor explicit id, and only a root, ProjectIDForLocationRoot(location, root) derives an id from the path — the legacy behaviour, now demoted to last resort.
×Otherwise: fail. No binding, no id, no root → an explicit error. The function never invents a project.

In every case, the folder's (location, root, machine) is recorded as Workspace metadata, never as the project's identity. cwd is context; it tells you where a workspace is, not which project it is.

5. The wlt_ link token

A new credential type, wlt_ (workspace link token), carries the project binding. It is modeled directly on the existing API key (ak_) path — same minting, same hash-only storage, same validation shape — with one addition: it binds a project (and optionally a workspace), not just a user.

TokenPrefixBindsUsed by
Session tokenses_userWeb UI bearer.
API keyak_userProgrammatic MCP callers. No project binding.
Bootstrapagen8-localuser localSingle in-memory local MCP token.
Link tokenwlt_user + project (+ workspace)The shim, from a marked folder. new

Why a token rather than letting the shim send a bare project_id: a token makes the project binding server-side and unspoofable. The server validates the token and reads the bound project from its own store. An MCP caller cannot assert membership of a project it was never granted. The raw token is shown once at mint time and stored only as a SHA-256 hash, exactly like an API key.

// internal/services/auth/linktoken/key.go  (new — mirrors apikey)
type LinkToken struct {
    ID          ID
    UserID      user.ID
    ProjectID   string             // opaque; auth never imports the project domain
    WorkspaceID string             // opaque; optional, bound once the workspace exists
    Label       string
    Prefix      string             // "wlt_" + first chars, for display only
    TokenHash   string             // SHA-256; raw shown once at mint
    ExpiresAt   *time.Time
    RevokedAt   *time.Time
    CreatedAt   time.Time
}

func (t LinkToken) IsActive(now time.Time) bool { /* not revoked, not expired */ }

// internal/services/auth/app/service.go  (new methods)
//   CreateLinkToken(ctx, params)  -> raw "wlt_..." returned once
//   ValidateLinkToken(ctx, raw)   -> { User, ProjectID, WorkspaceID }
//   RevokeLinkToken(ctx, id)

Minting reuses the existing primitives: auth.NewRawToken("wlt", n) for the prefix_hex string and auth.HashToken for storage. Persistence reuses the auth SQL store with explicit schema changes and preserving migrations so existing local data is not replaced by startup behavior.

6. The local shim

The shim already exists. RunHTTPBridge (internal/mcp/http_bridge.go) is a stdio-to-HTTP forwarder: it speaks stdio MCP to the harness and Streamable HTTP to the daemon, local or hosted, and already injects a per-session header. agen8 mcp serve is a thin CLI subcommand over that existing logic plus marker reading.

Harness side
The harness (Codex / Claude Code desktop or terminal) launches agen8 mcp serve as a stdio MCP server. No claude -p, no terminal-only assumption.
Marker read
The shim finds ./.agen8/ from cwd, reads workspace.json (server_url, project_id) and token (the wlt_). A missing marker is the unmarked-folder case; a malformed one is an error.
Connect
Opens HTTP to server_url/mcp, sends the wlt_ token, and reports (location, root, machine) as workspace metadata plus the per-conversation native session ref.
Proxy
Forwards every MCP tool call between harness and daemon. The session is now bound to the right project and registered as a member.
What changes inside the shim. Today bridgeSessionID() caches a per-folder UUID at ~/.agen8/bridge-sessions/<sha256(projectRoot)>.uuid — that is path-as-identity again, one layer down. The target shim drops that cache in favour of the marker's token for the project axis, keeping the per-conversation ref for the member axis.

7. Two identity axes

The design keeps two concerns apart that were previously tangled. They compose; neither blocks the other.

Because the axes are independent, the Project ↔ Workspace model ships and delivers value without first solving Claude's per-conversation session identity. A marked folder lands every session in the right project immediately; sharpening which member a Claude conversation is can follow later without reopening this design.

8. Integration points

This design touches exactly two existing decision points. Everything else is additive (a new token type, a new entity).

Point 1 · token resolution — daemon.resolveMCPSession

An unknown MCP token falls through to ValidateAPIKey. A wlt_-prefixed token is recognised first and validated as a link token, producing a session pre-bound to a user and a project. The mcp.Session type carries a ProjectID field for that binding.

// internal/daemon/daemon.go — illustrative
func (d *Daemon) resolveMCPSession(ctx context.Context, token string) (mcp.Session, bool) {
    if sess, ok := d.tokens.Resolve(token); ok {
        return sess, true                       // bootstrap + web-registered tokens
    }
    if strings.HasPrefix(token, "wlt_") {
        bind, err := d.AuthSvc.ValidateLinkToken(ctx, token)
        if err != nil {
            return mcp.Session{}, false             // invalid / expired / revoked — fail, no fallback
        }
        return mcp.Session{
            UserID:    bind.User.ID,
            ProjectID: bind.ProjectID,            // authoritative project binding
        }, true
    }
    if user, err := d.AuthSvc.ValidateAPIKey(ctx, token); err == nil {
        return mcp.Session{UserID: user.ID}, true  // existing ak_ path, no project binding
    }
    return mcp.Session{}, false
}

Point 2 · project resolution — RegisterMCPContext

At internal/services/project/app/mcp_context.go, project resolution consults the session's token binding first, demotes the path hash to a true fallback, and records the folder as a Workspace.

// internal/services/project/app/mcp_context.go — illustrative
projectID := session.ProjectID                          // 1. authoritative: link-token binding
if projectID == "" {
    projectID = types.ProjectID(strings.TrimSpace(input.ProjectID))  // 2. explicit caller id
}
root := strings.TrimSpace(input.ProjectRoot)
if projectID == "" {                                  // 3. fallback only
    if root == "" {
        return RegisterMCPContextResult{},
            fmt.Errorf("no project binding: marker, project_id, or project_root required")
    }
    projectID = ProjectIDForLocationRoot(locationID, root)  // legacy path hash
}

// record (location, root, machine) as a Workspace — metadata, never identity
_, err = s.workspaces.Upsert(ctx, workspace.Record{
    ProjectID: projectID, LocationID: locationID, Root: root, Machine: machine,
})

9. Onboarding (UI-first)

The primary flow is the web UI, not the terminal. There is no agen8 init that builds everything from the shell. A CLI helper may exist, but only to support the UI-led flow.

1In the Agen8 web UI, the user creates or selects a Project.
2They click “link this folder” for a local path. The UI mints a wlt_ link token for that user + project.
3The marker is written: ./.agen8/workspace.json (committed), ./.agen8/token (gitignored), and ./.agen8/.gitignore.
4agen8 mcp serve reads the marker and connects. The harness session registers into the bound project.
