Architecture · Last-seen Service

Last-seen Service

The last-seen service tracks each caller’s latest dashboard-open marker per project. The browser reads this value through lastseen.get and updates it through lastseen.markSeen after the user dismisses “Since you were away.” The behavior is durable in SQLite and scoped by the authenticated user and project.

1. Purpose and ownership

The service exists to compute a safe “since you were away” window for the dashboard. It stores one UTC timestamp per caller and project. The timestamp is a durable high-water mark: values before it are considered already acknowledged.

The service ownsThe service does not own
The store keyed by (user_id, project_id) and associated seen_at timestamp.Dashboard cards, list rendering, or event stream calculations.

2. Scope: per user + project marker

The marker is composite-keyed by authenticated user ID and target project ID. A missing row means the client must treat the marker as blank ("" in JSON responses), which implies “everything is new” for the diff computation.

The store accepts trimmed string IDs and rejects empty user/project IDs. Invalid inputs fail fast with 400-style invalid-parameter mapping from upstream handlers.

3. Service boundary

The application-level store is implemented in internal/services/lastseen and follows a minimal Store pattern (constructor + query + upsert semantics). The service constructor validates that the handle is present and that the dialect is SQLite, then runs a local CREATE TABLE IF NOT EXISTS.

MethodBehavior
Get(ctx, userID, projectID)Returns time.Time for that key, or ErrNotFound when absent.
MarkSeen(ctx, userID, projectID, now)Upserts seen_at to provided UTC timestamp; reusing keys updates existing records.

4. Persistence and schema

The table is small and intentionally schema-local, with no separate migration versioning path. It is created from the store constructor when the service boots. 

CREATE TABLE IF NOT EXISTS user_project_last_seen (
    user_id    TEXT NOT NULL,
    project_id TEXT NOT NULL,
    seen_at    TEXT NOT NULL,
    PRIMARY KEY (user_id, project_id)
)

Timestamps are serialized with time.RFC3339Nano and normalized to UTC.

5. RPC surface

The RPC adapter is registered in internal/rpc/lastseen.go and wired during daemon construction.

MethodRequestResponseNotes
lastseen.get { projectId: string } { seenAt: string } Reads callerIdentity.UserID from context and returns "" if no row exists.
lastseen.markSeen { projectId: string } { seenAt: string } Writes current UTC timestamp and returns the saved timestamp string.

6. Frontend integration

Dashboard “since you were away” state uses the marker in a pure diff step:
read previous seenAt first, compute diff, then call lastseen.markSeen when the user dismisses the card.

  • web/src/hooks/useLastSeen.ts calls both methods and invalidates cache after markSeen.
  • web/src/lib/sinceYouWereAway.ts treats an empty marker as no diff to avoid a first-load flood.
