Space-First Terminology Map

This document defines the naming contract for Agen8's space-first coordination model. Runtime, API, schema, and UI language use space and member for coordination identity. External harness vocabulary remains isolated to harness-specific surfaces.

2. Run ownership

A space is the coordination and context boundary. A SpaceMember is the live actor. When Agen8 provisions a managed member, the member receives a run because the harness delivery layer needs a concrete execution/session address. That run belongs to the member's managed harness session.

Do not introduce run-backed spaces. Managed member behavior derives from the SpaceMember record, MemberType, harness kind, and execution settings. It does not derive from hidden space containers or role-owned runs.

3. Member types

Member type answers: what structural behavior is this member allowed to perform inside a space?

TypeStructural meaningNotes
coordinatorActive coordinator for a space.At most one active coordinator per space. A coordinator remains a coordinator even when no workers are present.
workerMember that can receive, claim, and submit work.May have any optional role.
reviewerTransitional dedicated review member.Prefer migration to review policy or review capability.

Member type influences structural permissions and default tool exposure. It does not imply a domain role such as backend engineer or market analyst.

4. Roles

Role answers: what capability, persona, or domain expertise does this member bring?

Examples
Domain capability
Backend engineer, market analyst, product strategist, artist manager, macro researcher.
Sources
Managed or ad hoc
A role can come from an Agen8-managed role definition, an ad hoc capability declaration, or no role at all.

When a role exists, registration captures an effective snapshot and preserves source metadata.

5. Configuration terms

Member-facing contracts avoid ambiguous model or reasoning fields. They identify whether settings are defaults, desired settings, actual runtime settings, or harness constraints.

6. Lifecycle terms

LifecycleStates
Spacedraft, open, paused, closed, archived, deleting
SpaceMemberpending, active, inactive, disconnected, left, removed, expired
Harness sessionnot_started, starting, running, suspended, stopped, failed, unknown

SpaceMember lifecycle and harness lifecycle are related but not identical. A managed member can remain registered while its harness run is starting, stopped, failed, or disconnected.

7. Naming rules

  1. Use member_type for coordinator, worker, and transitional reviewer.
  2. Use role only for capability, persona, or domain function.
  3. Use space_template for reusable space setup.
  4. Use space for the live coordination/context boundary.
  5. Use member for actor attribution.
  6. Use harness_session for external execution metadata.
  7. Use desired_* and actual_* prefixes for execution settings.
  8. Avoid introducing agent as the primary domain noun unless it means a broad product actor. Prefer member in space coordination APIs.
  9. Do not expose run_id as the main actor identity in new APIs.
