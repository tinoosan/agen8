Architecture · Daemon

Daemon process host

The daemon is the process host for agen8 services. It builds the application once, wires JSON-RPC registrations, selects a listener strategy, handles first-run onboarding, and stamps secure request identity before calling the transport-agnostic RPC server.

1. Responsibility

internal/daemon owns process orchestration. It is the only layer that knows whether the process is serving local IPC or HTTP. It never changes RPC method semantics based on the listener strategy.

2. Listener strategies

Local IPC and HTTP are first-class daemon modes. Local is the default for native workflows. HTTP is explicit for Docker and hosted-shaped workflows.

StrategyEndpointAuthenticationUse case
local--endpoint / AGEN8_RPC_ENDPOINTResolved local user identity; no spoofable identity headersNative desktop and local development
http--http-addr / AGEN8_HTTP_ADDRAuthorization: Bearer <session-token> for browser requests after setupDocker and hosted-shaped operation

4. Identity and auth

The daemon stamps rpc.Identity into request context before calling the RPC server.

type Identity struct {
    UserID   string
    MemberID string
    Role     string
}
ModeIdentity sourceSecurity rule
Local IPCLocal process/user resolutionThe daemon ignores client-supplied identity headers or params.
HTTPUser service session validation/rpc rejects missing, invalid, or expired bearer tokens once setup is complete.
SetupOne-time setup token held by daemon and omitted from startup logsSetup routes fail closed after the first user exists.

The account role is a hosted account role. admin and user are not coordinator or worker roles.

5. First-run setup

When the user service reports zero users, the HTTP daemon exposes first-run setup and prints a setup entrypoint without the one-time setup token. The setup token stays out of process logs while the setup routes continue to validate it before creating the first account user as admin and returning a real browser session token. Setup does not create a project, project, member, task, agent, or API key.

6. Dev web proxy

The daemon is the only browser entry point in development and production. Vite exists only as a hot-reload asset server. When AGEN8_DEV_WEB_URL is set, the daemon keeps protocol routes for itself and reverse-proxies the remaining web UI requests to Vite. When the variable is unset, the daemon serves the embedded frontend from internal/web/dist.

RequestDev ownerProduction owner
GET /setup, POST /setupDaemonDaemon
POST /rpcDaemonDaemon
GET /eventsDaemonDaemon
GET /healthzDaemonDaemon
GET /, /assets/*, Vite client/HMR pathsDaemon reverse proxy to ViteDaemon embedded frontend

make dev and make dev remote start the HTTP daemon under Air and start the Vite server. The browser opens the daemon HTTP URL. Vite provides hot-reload assets, and Air rebuilds and restarts the daemon after Go source changes.

make dev
make dev remote

# daemon browser/RPC URL: http://127.0.0.1:7777
# Vite asset server: http://127.0.0.1:5173

First-run setup stays seamless in dev mode. The setup URL opens on the daemon, form submission creates the first account user and stores the session token, and the redirect to / returns through the daemon into the Vite-backed React app. React still calls /rpc on the daemon.

7. Code layout

cmd/
  main.go                  # cobra root and daemon start command

internal/
  daemon/
    config.go              # listener config, env defaults, validation
    daemon.go              # Application + RPC registry + strategy selection
    local.go               # local IPC listener strategy
    http.go                # HTTP listener strategy, /healthz, /rpc, /events, setup, web UI/proxy
    daemon_test.go         # listener and setup tests

  web/
    server.go              # embedded SPA handler used when no dev web URL is configured
    dist/                  # compiled frontend assets

  app/
    application.go          # field-only Application and NewApplication

  rpc/
    server.go              # shared JSON-RPC server
    registry.go            # method registry
    identity.go            # request identity context
