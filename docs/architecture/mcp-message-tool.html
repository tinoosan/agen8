Architecture · MCP Message Tool

MCP message tool

The agent-facing communication tool for sending routed messages between members and projects.

Purpose

message is an MCP tool, not a service API. It exposes the product-facing communication contract to member harnesses and maps each action to typed application service calls. The handler owns request decoding, destination resolution, role-aware policy, message-envelope construction, and deterministic result shaping.

Boundary. Message tool behavior lives in internal/mcp/tools/message. The message service owns durable message persistence and delivery wakes. The channel service owns channel identity and routability. The project service owns project records and the member roster subdomain. The MCP project tool owns discovery only; it does not send messages. No service accepts raw message(...) tool JSON, and no service package defines a message-tool-specific service or port.

Actions

send Validate content and destination, resolve recipient labels, build a durable member-message envelope, publish it, and return the resolved route. Control flow

Application wiring

The application composition root constructs ProjectSvc, ChannelSvc, and MessageSvc once. ProjectSvc supplies both project records and member roster lookups through narrow handler-owned interfaces. When the runtime supervisor spawns a managed harness, it registers an MCP session token that carries those interfaces. The MCP server resolves the session token and supplies the services to the native message handler.

// MCP session bootstrap
tokenStore.Register(token, agen8mcp.Session{
    ProjectReader:      app.ProjectSvc,
    MemberDirectory:  app.ProjectSvc,
    ChannelReader:    app.ChannelSvc,
    MessagePublisher: app.MessageSvc,
    ProjectID:          projectdomain.ProjectID(projectID),
    MemberID:         memberID,
})

// internal/mcp/server.go
message.NewHandler().Handle(ctx, message.CallContext{
    Projects:   session.ProjectReader,
    Members:  session.MemberDirectory,
    Channels: session.ChannelReader,
    Messages: session.MessagePublisher,
    ProjectID:  string(session.ProjectID),
}, arguments)

Handler contract

The message handler receives narrow dependencies at call time. It does not import internal/app; the MCP server imports the handler and supplies concrete services from the session.

Request model

FieldUsed byRule
actionsendRequired. One of send.
destination_member_idsendRequired. Routes to an active member returned by project(action="member_list") in the caller's project.
kindsendOne of inform, query, ack, response.
subjectsendRequired non-empty semantic subject.
bodysendRequired non-empty message body.
correlation_idack, responseRequired for reply semantics and omitted for unrelated inform/query messages. Preserves the request/response thread.

The schema requires only fields used by send. Optional fields are omitted when unused. Explicit null values are rejected before service calls.

Destination rules

DestinationResolutionEnvelope route
